# OPC — אפיון מערכת מחייב

**Optical Center · גרסה 2.1 · 10.11.2026**

מקור: אפיון גרסה 2.1 שנמסר בידי בעל הפרויקט בשיחה מ־10.11.2026. המסמך שומר את 20 סעיפיו ומעניק לדרישות מזהים קבועים לצורך פיתוח, בדיקות וקבלה. הוא מגדיר יעד מחייב; הוא אינו אישור שהמימוש קיים או עובד בפרודקשן.

מסמך MaxStudy מ־2.11.2026 ורשימת 13 תחומי היכולת שנמסרו קודם הם מקורות ההקשר. במקום שיש דיוק עסקי חדש בגרסה זו, הנוסח המפורש כאן הוא הקובע. בפרט: ארי מאשר התקשרות ומחיר, מנהל החנות מתאם את הביצוע ומאשר פתרון, ו־PWA נבדקת גם כשהיא מותקנת בפועל.

מפת ההתאמה למקורות ולמימוש: [OPC_GAP_ANALYSIS_V2_1.md](OPC_GAP_ANALYSIS_V2_1.md). אין לשנות סטטוס קבלה על סמך שינוי קוד בלבד.

### ראיות הדרושות לקבלה

לכל בדיקת קבלה נשמרים גרסה/commit וכתובת סביבה, תפקיד הבודק, תאריך, שלבי הבדיקה, מזהי הרשומות הרלוונטיים, התוצאה בפועל והראיות. בדיקה חיה מוסיפה אישור שמירה במסד ומצב מסירת הודעות; בדיקת PWA מוסיפה מכשיר, מערכת הפעלה, דפדפן ואופן ההתקנה.

אין להסיק ״עובד בפרודקשן״ מבדיקה בנתוני זיכרון, תגובת API מדומה, dry run, בדיקת טיפוסים, הצלחת build או קיום cron בקובץ תצורה.

### מסע קבלה קצר לארי

1. ארי רואה דיווח חדש, את הדחיפות ואת הפעולה הבאה.
2. הוא פותח תוכנית טיפול, בוחן עבודות נוספות מתאימות ומאשר את ההיקף.
3. הוא מגיע למידרג הרלוונטי, מתקשר, מזין את התנאים ומאשר עבודה ומחיר.
4. מנהל החנות מקבל פרטים, מתאם ומאשר או דוחה את הפתרון.
5. ארי רואה סגירה מהימנה, היסטוריה ועלות; חריגים חוזרים אליו עם פעולה ברורה.

המסע צריך להיות אפשרי גם כשארי עצמו הוא המדווח, בלי להחליף זהות או לבטל בקרה עסקית.
